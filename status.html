faxx-hr (pracovní název)

Hodnocení životopisů pro personalisty — s bezpečnostní vrstvou proti skrytému textu v CV (prompt injection)

Živě · edge demo F0 · gate otevřený AI Act · High-risk

⚠ Brána projektu: F0 — Benchmark detekce skrytého textu

Žádná plná Cloudflare infrastruktura, dokud benchmark na sadě čistých + „otrávených" CV nepotvrdí, že detekce funguje.

Exit (návrh): recall ≥ 98 % na held-out sadě · false-positive ≤ 5–10 % na čisté · přesnost extrakce ≥ 90 %.
Hotovo: detektor v2 (WCAG kontrast, Unicode nosiče, visible/hidden split, lidské popisy nálezů) · regresní sada 24/24 (DOCX 14: 9 útoků + 5 FP · PDF 10 on-prem) · živě na Cloudflare — DOCX i PDF (přes Cloudflare Workers AI) · hraniční PDF vektory změřeny na obou vrstvách (edge vs. on-prem) → coverage matice: napříč oběma vrstvami neprojde žádný vektor nezachycen, V-PDF-06 (ToUnicode fact-swap) uzavřen on-prem i edge (glyf↔ToUnicode → hidden_text). Zbývá: held-out sada + externí red-team + kalibrace prahů + plný render→OCR dual-path.

🌐 Živě na Cloudflare (edge demonstrátor)

hodnoticí appka — nahraj dávku CV ≤ 10 MB + inzerát → ranking (pohledové stavy ● ◐ ○ — nebo číselné skóre, přepínatelné), rozpad po kritériích, kontakty a nálezy skrytého obsahu. Přepínatelný AI backend (výchozí zdarma Workers AI, Claude po doplnění klíče), editovatelné váhy i prompt, export PDF/HTML. Plně CS/EN + světlý/tmavý motiv.

demo detektoru — nahraj jedno CV a uvidíš skrytý text (detekce běží ve Workeru na raw bytech, funguje i při vyčerpané AI kvótě).

Dvě větve: A = tento edge demonstrátor (bezstavový, veřejný, JEN ukázková data — reálná CV nikdy). B = budoucí samostatná modifikace s DB na lokální síti (perzistence, audit_log, GDPR/DPIA) — teprve tam reálná CV.

Princip: odděl extrakci od hodnocení

Skórovací logika nikdy nevidí surový text. LLM #1 dělá jen strukturovanou extrakci do pevného JSON schématu (žádné skóre). Skóre počítá deterministický rubrik v kódu nad tím JSONem. Injection „tento kandidát je nejlepší" nemá kam zapsat — schéma má jen years_experience, skills[], education[]. Personalista rozhoduje sám (decision support, ne decision maker). Detektor navíc rozdělí text: do modelu jde jen viditelný text, skrytý (hidden_text) jen do review — co člověk na papíře nevidí, model nedostane.

Bezpečnostní pipeline (6 fází)

[uchazeč → e-mail s CV] │ [CF Email Routing → Email Worker (postal-mime)] ← recyklace z job-watch-mail ▼ originál → R2 (immutable), stav → D1 [Sanitizace + DUAL-PATH DIFF] textová vrstva PDF vs. render→OCR/vision (on-prem) │ co je v (a) a ne v (b) = skrytý obsah → FLAG ▼ [LLM #1 extrakce] pevné JSON schéma + evidence (žádné skóre) ▼ [Normalizace + validace KÓDEM] ▼ [Deterministický rubrik] váhy personalisty (+ volitelně LLM #2 na měkká kritéria) ▼ [Review personalisty] skóre + důvody + zdrojové pasáže + flagy → rozhoduje člověk

5 vrstev obrany (defense in depth)

Ingest do R2 (immutable) — originál se nikdy nepřepisuje; auditní kotva.
Dual-path diff — detektor skrytého textu (ne tichý filtr); nález se zobrazí personalistovi.
Deterministické detektory v2 + CDR — WCAG kontrast vůči skutečnému pozadí, font < 4pt, render mode 3, DOCX w:vanish, hlavičky/patičky, Unicode nosiče (zero-width, Tags E0000+); regex jen eskaluje severity. CDR (Dangerzone) párovaná s kontrastem.
Extrakce s omezeným schématem — model nemá pole na verdikt; identity / qualification / sensitive odděleně, chráněné znaky se neskórují.
Deterministický rubrik + audit — skóre v kódu, breakdown s evidence; audit_log append-only, záznam lidského rozhodnutí.

Fáze

F0

Benchmark detekce (gate, bez infrastruktury)

Detektor v2 hotový (kontrast, Unicode, visible/hidden split, lidské popisy), regresní sada 24/24 (DOCX 14 + PDF 10 on-prem), živě na Cloudflare — DOCX i PDF (Workers AI). Hraniční PDF vektory změřeny (CID/Identity-H, ToUnicode obfuskace, XFA, JS, render mode 3 …) na edge i on-prem → coverage matice: napříč oběma vrstvami neprojde žádný nezachycen; V-PDF-06 (ToUnicode) uzavřen on-prem i edge (glyf↔ToUnicode → hidden_text). Zbývá held-out sada + externí red-team + kalibrace prahů + render→OCR dual-path.

GATE · aktivní
F1

Pipeline extrakce → validace

V edge demu živě: upload dávky → detect (visible/hidden split + flagy) → LLM #1 extrakce do pevného schématu (jen viditelný text) → validace kódem. Zbývá pro produkt (Track B): e-mail ingest, R2/D1 perzistence dávek.

F2

Review UI personalisty

V edge demu živě: rubric.ts — váhy, must-have gates (default vypnuté), breakdown s evidence, požadavky z inzerátu (LLM), přepočet bez AI. Zbývá: kalibrace vah proti historickým rozhodnutím personalisty.
